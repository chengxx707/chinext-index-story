## 真实相册的阻碍

当前合格历史照片为**0张**。三个上传ZIP已复查：文献存档有18份HTML和1份PDF，数据底稿没有照片，工程种子中的图像是地球与参考海报；没有可直接抽出的历史现场照片。

已有人民网、央广／新华社、澎湃等原报道和图注线索；最明确的线索是2020.08.24上市仪式照片。当前原页请求仍被运行环境出站白名单403拦截。访问要求已保存为网络配置草稿，草稿尚未应用到运行环境；不能将访问失败解释为原页没有照片。具体来源、优先级与入库条件见[真实照片获取状态 V2](真实照片获取状态_V2.md)。

`make photo-status`可诊断状态；`make album`及`make ending`在照片未ready时失败。取得并核对真实图片前，不再渲染无照片文献／文字结尾。旧39秒文献版和旧15秒组件只作被拒绝的历史对照。

## 已保留的工程保护

- 基日、非交易日和盘中政策与真实收盘分开，明确冻结政策拍；下一拍到达真实观察日后才显示新卡。
- 原始来源、资格、主表、字体、资产及派生配置在编译、缓存命中、存储与装配前后均校验；worker读取冻结的主表快照。
- 修正并行编码可能等待不退出：绘制worker改用spawn启动，防止继承编码管道或原生绘图库状态；新增有超时的真实并行CLI回归。

这些保护继续使用；技术及静帧检查不代表V2已获用户观看通过。

## 可重复运行

```bash
make production-check
make test
make components
make representative
make photo-status
make album
```

`representative`生成当前V2代表范围并复用有效场景缓存，最终装配仍须重新检查。`components`输出八类、32秒非相册组件预览；`album`和`ending`受照片ready检查保护，当前会失败。只有明确做历史对照时使用`make legacy-ending`。缓存／逐帧数据保留在忽略的`output/`目录，精选副本应在本轮检查完成后更新。
