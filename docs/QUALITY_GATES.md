质量检查与放行规则

本项目当前先交付无声代表样片。自动检查通过表示检查范围内没有发现硬错误；不表示美术已达到海报、叙事已获用户认可或全片已完成。

从仓库根目录执行：

```bash
.venv/bin/python tools/validate_project.py --layout --output output/v6_review/validation.json
.venv/bin/python tools/validate_project.py --layout --video output/v6_review/chinext_v6_sample.mp4 --output output/v6_review/validation.json
.venv/bin/python -m pytest -q
```

视频文件名以实际 render_v6.py 生成的路径为准；可以向 `--video` 传入该路径。`--config`、`--events`、`--csv`、`--assets` 可显式指定。不要用旧报告替代当前输入的检查。

脚本始终写 JSON 报告；必需检查失败时进程退出码为 1。报告记录输入 SHA256、实际执行范围、逐项结果和待人工审阅项。不带 `--layout` 或 `--video` 时对应范围写 `not_run`，不能据此声称布局或成片通过。

**事实与时间检查**

- 直接检查原始 CSV 的日期顺序与唯一性，OHLC 是否完整、正数且满足低≤开/收≤高；不会让模型加载器的排序掩盖坏输入。
- 检查所有实际帧的日期与真实交易日收盘一致，禁止把过渡插值标成该日真实收盘。
- 帧数与配置一致，首帧和最后有效帧达到规定日期。
- 被禁用或非 A/DATA 事件不能泄漏进模型；配置中也不得误启用未核验事件。
- 启用A级事件必须能解析到统一台账的A级记录、可恢复的研究文档与章节；数字和日期精度/交易日锚点不得偏离来源。此项不冒充重新在线核验。
- 事件命中时间对应真实日 K，并检查首次到达该时间的实际帧；不能只比较两套手填字符串。
- 关键点数值从 CSV 核对、命中日正确、镜头中可见。
- 阶段状态单一、数值由实际收盘和锚点计算、回调使进度真实后退。实际绘制的一根轨由布局诊断另行核对。
- 稳定取景镜头在入口过渡后保持纵轴不变；入口默认0.7秒属于摄影机转换，不误判为阅读期呼吸。

**布局检查**

绘制器使用实际字体和 `ImageDraw.textbbox` 记录文字框，在事件、极值与首尾等代表帧检查边界和文字重叠，同时检查关键锚点和实际活动轨数量。装饰线条不当作文字框。文字框不溢出并不证明手机上读得完；完整显示的停留时间、视觉焦点和质感仍须审看实际片段。

**视频检查**

FFprobe 检查一个视频流、无音轨、分辨率、帧率、帧数、时长；FFmpeg 使用 `-xerror` 完整解码并检查超过0.1秒的近乎全黑段。默认严格对照正式配置。`--preview` 仅按渲染manifest声明的预览尺寸检查，报告明确标记为 preview，不能替代正式分辨率检查。

渲染目录中的 `render_manifest.json` 必须存在，并检查其中 config/events/csv SHA256 与当前输入一致，同时检查生产源码树与PNG资产哈希，防止用旧画面验证新源码。缺少manifest会阻止媒体放行，不把文件存在等同于当前运行产物。脚本能证明解码和量化属性，不能证明未声明的剪辑意图或主观美感。

**独立审看与自动修复**

自动检查后，查看目标分辨率关键帧和实际导出，对照批准海报及纳斯达克100视频的动态参考，按“版本—时间码—问题—严重程度—预期—修复—复检”记录结果。美术低于母版、关键文字读不完、极值没有重音等，仍属于必须修正项。禁止以单一模型分数或硬检查全绿宣布美术通过。

测试包含故意错误的 OHLC、重复日期、插值 HUD、缺失终点、提前事件、禁用事件泄漏、文字越界/重叠和预览冒充正式分辨率；这些坏例必须被拒绝。代表样片供用户集中审阅前，事实、时间、布局和媒体硬错误应已由开发者修正。
