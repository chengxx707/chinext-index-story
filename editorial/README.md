# GPT 内容生产交接区

本目录保存 GPT 的事实复核、叙事、屏幕文字和导演配置。生产代码、冻结主表和原始资产仍由原路径管理。

当前交付见 [2015 年内容候选](2015/README.md)。最新用户已授权 GPT 自主完成资料复核、内容加工、候选配置和 GitHub 分支交付；Codex 可以继续候选接收、适配、校验与预览。

## 版本规则

- 一次可复现交付放入 `2015/releases/vX.Y.Z/`，发布后保留旧版，不原地覆盖。
- 影响叙事、选用事实或镜头时长的修改升次版本；仅修复错字、链接或交接错误升补丁版本；不兼容的数据契约升主版本。
- Git commit 固定文件内容，`manifest.json` 固定输入摘要和产物摘要。`2015/README.md` 只指向当前候选，不代表用户已验收画面。
- GPT 写内容候选及其报告；Codex 的接收、适配与渲染结果放在独立 `output/` 目录，并记录所用候选的 commit、版本及 SHA-256。
- 使用候选时，先校验再导入。不要重新运行旧硬编码 `pilot.py` 来覆盖 GPT 的镜头选择。
- 正式主表的采用与集中视觉评审沿用现有项目检查点。完成文件提交不等于另一个 Codex 会话已经被启动。

## 本轮执行步骤

1. 读取两份外部资料包和现有工作流契约，核对字节摘要与来源映射。
2. 逐条审核 39 个外部事件，分清事实、机构/专家观点和编辑解读；修订可上屏文本。
3. 从冻结日线重新计算关键价位、区间涨跌及完整向下缺口。
4. 写出连续历史叙事、逐镜屏幕文字和统一日期驱动的导演配置。
5. 按现有 Schema 验证候选记录，检查帧区间、数据引用和事件时序；记录尚未执行的渲染评审。
6. 提交到独立候选分支，提供可直接执行的 Codex 交接文件与本轮报告。

执行证据和具体结果保存在版本目录。状态必须根据实际产物更新，不能仅凭计划标记完成。
