# OPS-001.1 · 本地生产调度

在仓库根目录使用现有的 Python 3.12 虚拟环境。调度器本身只使用 Python 标准库，生产适配器沿用现有 Makefile、工具脚本、依赖和素材。

```bash
.venv/bin/python -m orchestration dry-run
.venv/bin/python -m orchestration run --jobs 2
.venv/bin/python -m orchestration report
.venv/bin/python -m orchestration report --format json
.venv/bin/python -m pytest -q tests/orchestration
```

`dry-run` 给出当前输入摘要、依赖和就绪情况。它不运行适配器，不写任务记录，也不预测尚未执行的前置任务会通过。`run` 默认执行主表、照片就绪、全片编排粗预演、静态组件检查和 2015 研究与内容链。两线中依赖已满足的任务可并行运行，默认最多两个。发现任务失败时退出码为 1。审批待定、前置未通过、素材缺失或入口未实现以 `BLOCKED` 记录，缺少运行前提本身不使 CLI 失败。CLI 用法、状态锁或工作流配置错误退出码为 2。

| 生产线 | 调度范围 |
| --- | --- |
| A · 完整视频 | 主表与逐字稿核对 → 全片时间表编译。独立诊断真实照片 → 相册代表段。主表编译后即可生成全片编排粗预演。全片成片要求正式相册、全片内容批准、主体视觉批准、实际全片画面预演和独立成片授权。 |
| B · 视觉 | 当前主表驱动的组件静帧与边界检查 → 2015 主体代表段。主体视觉评审只依赖主体代表段通过技术检查。 |

任务、依赖及输入在 [production.json](registry/production.json)。全片编排粗预演可在浏览器按节拍查看，照片位置有明确占位。全片画面预演和目标规格渲染仍缺生产入口。照片诊断调用 `make photo-status`，读取有效照片数量和年份。达到该检查的最低门槛后，原有相册渲染器还会逐节点核对素材。

## 人工门禁

准备后续经明确授权的工作时，先查看 `dry-run` 中任务当前的 `input_hash`。用户批准后，以批准人和实际决定记录该节点，示例中的摘要须替换为计划中的 64 位十六进制值。

```bash
.venv/bin/python -m orchestration approve B.representative-render \
  --input-hash "<当前输入摘要>" --actor "<批准人>" --note "<批准范围与决定>"
```

所有前置任务须已通过。批准仅写入本地审批记录。实际运行已获批的代表片渲染还要显式使用 `run --allow-render`。用户看完成品后的主体评审和全片评审是独立人工节点，采用同一审批命令并记录实际观看决定，随后由 `run` 处理。执行人工节点时的 `PASSED` 表示已记录该决定。渲染适配器的 `PASSED` 表示现有工具的技术检查通过。

## 状态、重试与证据

正常路径为 `PENDING → READY → RUNNING → VALIDATING → PASSED`。未满足的前置与审批进入 `BLOCKED`，命令或校验错误进入 `FAILED`。同一任务 ID 和输入 SHA-256 对应一份记录，保留所有尝试。摘要纳入任务定义、声明文件内容、适配器与调度器代码，以及上游输入和通过检查的产物摘要。重复运行会复核 Manifest 和产物字节。输入或上游产物变化时，旧记录保留在历史中，对新摘要重新执行所需检查与审批。

自动重试仅适用于注册为安全的任务。当前编译和研究节点最多两次尝试，其余节点各一次。预算耗尽后再次调用 `run` 会保留失败结果，修复影响摘要的输入后可运行新输入。成功产物缺失或损坏时，同一任务下记录新的尝试。工作流中断后，下次执行会将未完成尝试记为失败，按原预算处理。

默认目录 `output/orchestration/` 会被 Git 忽略。可在全局参数 `--state-dir output/其他目录` 指定独立状态目录。

- `records/<任务>/<SHA-256>.json` 保存状态转换、尝试、退出码、错误、日志和 Manifest 路径。
- `attempts/<任务>/<SHA-256>/<序号>/` 保存合并后的命令输出 `command.log`、本次产物，以及通过校验时的 `manifest.json`。
- `approvals/<任务>/<SHA-256>.json` 保存首次明确批准的人员、决定和时间。
- `report` 统计当前输入对应的持久化记录，并附历史记录数。计划状态、审批文件和原仓库中的历史样片不会自动计作实际执行通过。

## 当前范围与下一阶段

- 当前是单机 Linux 工作流。状态目录加锁，多个独立状态目录之间没有共享资源配额。本地文件和命令由操作者信任，审批尚无身份认证、签名、撤回或远端同步。
- 摘要覆盖注册的输入和字体文件。Python 依赖使用锁定清单，系统工具与已安装解释器或库的二进制未纳入摘要。更换运行环境后可用新的状态目录验证。
- 阻断的相册仍需真实档案照片。已有代表视频没有作为本轮执行记录导入，受保护的代表段视频适配器本轮未实际编码验证。
- 从 2015 试点的证据缺口和候选审稿开始。主体集中审片、相册素材收集、全片编排检查可各自推进。全片画面预演与装配需要另行接入现有生产引擎。
